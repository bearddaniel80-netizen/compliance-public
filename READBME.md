# AQL Compliance Testing Framework

The AQL Compliance Framework validates AQL behavior across supported data sources and input types.

Unlike traditional unit testing frameworks, the compliance framework focuses on verifying that AQL produces consistent results across formats, sources, and execution modes.

The framework is designed to answer questions such as:

* Does `SELECT *` work for CSV input?
* Does filtering behave consistently across sources?
* Does `SHOW` return the expected schema?
* Does a dialect satisfy AQL compliance requirements?
* Did a recent change break query behavior?

---

# Why This Exists

AQL is intended to become a universal query layer across many data formats and data sources.

As support is added for new formats, dialects, and connectors, the compliance framework provides a repeatable way to verify behavior.

```text
CSV
JSON
XML
YAML
Logs
STDIN
Future Sources
      │
      ▼
AQL Compliance Framework
      │
      ▼
Consistent Query Behavior
```

The goal is not simply testing code.

The goal is testing AQL itself.

# Current Status

## Supported Inputs

| Input | Status       |
| ----- | ------------ |
| CSV   | Supported    |
| JSON  | Supported    |
| XML   | Supported    |
| YAML  | Supported    |
| STDIN | Supported    |
| Logs  | Experimental |

### Log Files

Log support is currently minimal.

The log source currently exposes only two fields:

```text
line
line_no
```

Advanced parsing, pattern extraction, and structured log analysis are planned for future releases.

## Report Formats

### Available Today

```text
rich
html
json
markdown
junit
pdf
csv
```

### Generated Today, Query Support Coming Later

The following formats can be generated by the reporting framework today.

The files are valid and portable, but AQL cannot query them yet.

```text
arrow
avro
duckdb
parquet
sqlite
```

Example:

```bash
compliance suite run core \
    --format parquet
```

Produces a valid Parquet file.

Future AQL support will enable workflows such as:

```bash
aql query "
SELECT *
FROM parquet('compliance.parquet')
"
```

---

### Under Development

The following outputs are currently stubs:

```text
mysql
postgres
```

Attempting to use them will raise:

```text
NotImplementedError
```

These formats exist to establish the future reporting API and extension points.

# Test Hierarchy

```text
Tag
 └── Suite
      └── Manifest
           └── Query
```

A query produces a TestResult.

A manifest aggregates TestResults.

A suite aggregates manifests.

A tag aggregates suites.

---

# Manifests

A manifest is the smallest executable test unit.

Run:

```bash
compliance manifest run <manifest>
```

List:

```bash
compliance manifest list
```

Example:

```bash
compliance manifest run stdin_csv_file
```

---

# Suites

A suite is a collection of manifests.

Run:

```bash
compliance suite run <suite>
```

List:

```bash
compliance suite list
```

Example:

```bash
compliance suite run core
```

---

# Tags

Tags provide logical groupings of compliance tests.

Run:

```bash
compliance tag run <tag>
```

List:

```bash
compliance tag list
```

Summary:

```bash
compliance tag summary
```

Example:

```bash
compliance tag run stdin_file
```

---

# Common Options

| Option            | Description                           |
| ----------------- | ------------------------------------- |
| --cache           | Cache query results                   |
| --profile         | Enable timing and performance metrics |
| --retry N         | Retry failed queries                  |
| --parallel N      | Execute using N workers               |
| --fail-fast-query | Stop after first query failure        |
| --format FORMAT   | Select report format                  |

# Examples

Run a manifest:

```bash
compliance manifest run csv_function
```

Run STDIN tests:

```bash
compliance manifest run stdin_csv_file
```

Run the core suite:

```bash
compliance suite run core
```

Run all STDIN compliance tests:

```bash
compliance tag run stdin_file
```

```bash
compliance suite run core \
    --format html
```

```bash
compliance suite run core \
    --format junit
```

```bash
compliance suite run core \
    --format duckdb
```

```bash
compliance suite run core \
    --format parquet
```

# Future Vision

As AQL expands, the compliance framework becomes the certification layer for new sources and dialects.

A new connector, parser, or dialect should be able to answer a simple question:

> Does it pass AQL compliance?

The compliance framework provides the mechanism to measure that consistently across the entire ecosystem.
